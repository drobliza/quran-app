# 📖 Quran App

تطبيق ويب عربي بسيط مبني باستخدام **Node.js** و**Express** و**SQLite** و**bcrypt**. يوفّر إنشاء الحساب وتسجيل الدخول، ثم يتيح للمستخدم المسجّل الوصول إلى صفحة القرآن حسب حالته.

## ✨ المميزات

- 🔐 تسجيل وإنشاء حسابات مع تخزين كلمات المرور باستخدام `bcrypt`.
- 🛡️ حماية نماذج تسجيل الدخول والتسجيل بواسطة CSRF token.
- 🚦 الحد من محاولات تسجيل الدخول المتكررة لتقليل محاولات التخمين.
- 🍪 جلسات آمنة باستخدام `express-session` مع `httpOnly` و`SameSite` ومدة انتهاء للجلسة.
- 🔄 تجديد Session ID بعد تسجيل الدخول لتقليل خطر Session Fixation.
- 🗄️ SQLite لتخزين المستخدمين.
- 📖 صفحة قرآن محمية لا يمكن الوصول إليها بدون تسجيل الدخول.
- 🌐 واجهة عربية RTL بسيطة ومتجاوبة.

## 🛠️ التقنيات

- Node.js
- Express
- SQLite3
- bcrypt
- express-session

## 🚀 التشغيل

### 1. تثبيت الاعتمادات

```bash
npm install
```

### 2. إعداد سر الجلسة

انسخ `.env.example` إلى `.env` وضع قيمة عشوائية طويلة لـ `SESSION_SECRET` (32 حرفًا على الأقل):

```text
SESSION_SECRET=ضع-هنا-سرًا-عشوائيًا-طويلًا
NODE_ENV=development
PORT=3000
```

> لا ترفع ملف `.env` إلى GitHub.

### 3. تشغيل التطبيق

```bash
node app.js
```

بعد التشغيل سيكون الخادم متاحًا افتراضيًا على:

```text
http://localhost:3000
```

## 🔐 تحسينات تسجيل الدخول

تم تشديد نظام المصادقة ليشمل:

- عدم وجود `SESSION_SECRET` ثابت داخل الكود.
- رفض تشغيل التطبيق إذا لم يتم توفير سر جلسة بطول مناسب.
- Cookies للجلسة بإعدادات `httpOnly` و`SameSite=Lax`، و`Secure` تلقائيًا في الإنتاج.
- CSRF token لطلبات التسجيل وتسجيل الدخول.
- تحديد محاولات تسجيل الدخول إلى 5 محاولات لكل عنوان IP واسم مستخدم خلال 15 دقيقة.
- رسائل خطأ عامة عند فشل تسجيل الدخول حتى لا يتم كشف وجود الحساب.
- مقارنة كلمة المرور باستخدام `bcrypt`، مع مسار dummy لتقليل اختلاف زمن الاستجابة للحسابات غير الموجودة.
- تجديد Session ID بعد تسجيل الدخول.
- التحقق من اسم المستخدم وطول كلمة المرور أثناء التسجيل.
- إزالة إنشاء حساب `admin` بكلمة مرور ثابتة من الكود.

## ⚠️ قبل النشر على الإنترنت

- استخدم HTTPS.
- ضع `SESSION_SECRET` في متغيرات البيئة ولا تضعه في Git.
- لا ترفع `users.db` إذا كانت تحتوي على بيانات حقيقية؛ `.gitignore` يمنع الملفات الجديدة من الإضافة، لكنه لا يزيل نسخة موجودة مسبقًا من Git history.
- يفضّل استخدام مخزن جلسات خارجي مثل Redis عند تشغيل عدة نسخ من التطبيق أو عند التوسع؛ `MemoryStore` المدمج في `express-session` مناسب للتطوير وليس للإنتاج واسع النطاق.
- إذا كانت قاعدة البيانات الحالية تحتوي على حساب `admin` قديم، راجعها واحذف الحساب أو غيّر كلمة مروره قبل النشر.
